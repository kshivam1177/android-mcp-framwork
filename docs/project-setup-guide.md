# AndroidMCP Framework — Project Setup Guide

This guide is generated by `androidmcp-framework setup` into
`.androidmcp-framework/SETUP.md`, next to your project's `config.yaml`.

## 1. Check the Android toolchain

From your project root, run:

```bash
androidmcp-framework doctor
```

Make sure Android SDK platform-tools (`adb`), Java, Gradle, and a connected Android emulator or physical device are available. If using a physical device, enable USB debugging and accept the computer's authorization prompt.

## 2. Understand the project configuration

Edit `.androidmcp-framework/config.yaml`. The setup command creates it if missing and does not overwrite an existing config.

- `enabledWorkflows`: MCP tool groups exposed to the agent.
- `sessionDefaults.projectPath`: project root; usually `.`.
- `sessionDefaults.module`: Android Gradle module, commonly `:app`.
- `sessionDefaults.variant`: build variant, commonly `debug`.
- `sessionDefaults.targetId`: optional ADB serial to pin a device.
- `paths.adbPath`, `paths.androidHome`, `paths.javaHome`: optional explicit toolchain paths.

The framework supports native Android projects and Flutter projects that build Android apps. Leave optional paths unset when the tools are already on your `PATH`.

## 3. Register the MCP server with your coding agent

Use the installed CLI rather than a local checkout path. A typical MCP server entry is:

```json
{
  "mcpServers": {
    "androidmcp-framework": {
      "command": "androidmcp-framework",
      "args": ["mcp"]
    }
  }
}
```

Add this entry to the MCP configuration format used by your client (for example, Claude Code, Codex, Gemini, or a compatible editor). If your client requires environment variables, provide the Android SDK paths there. Restart the client after changing its MCP configuration or this project's `config.yaml`.

For an ephemeral run without a global install, use `npx -y androidmcp-framework@latest mcp` if your client supports command arguments and `npx`.

## 4. Discover the available tools

```bash
androidmcp-framework --help
androidmcp-framework workflows
androidmcp-framework tools
androidmcp-framework tools --json
```

Use `snapshot_ui` to inspect the current hierarchy, `screenshot` for visual state, and the UI automation tools to interact with elements. Use `batch` for short sequences that can run without an LLM decision between every action. Assertions in a batch stop execution on failure.

## 5. Project artifacts and reports

Framework project data is stored under `.androidmcp-framework/`. Common locations include:

- `config.yaml`: project-specific settings.
- `screens/` and `screen-maps/`: learned or saved screen metadata.
- `workflows/`: reusable UI workflow definitions.
- `testcases/` and `test-reports/`: saved test cases and reports.
- `artifacts/screenshots/`: captured screenshots.
- `instructions/`: custom test instructions.

Keep generated test data and screenshots out of source control unless they are intentionally part of your fixtures. Do not store credentials, production customer data, or secrets in test instructions or reports.

## 6. Troubleshooting

- Run `androidmcp-framework doctor` and resolve required checks first.
- Run `adb devices -l` to confirm the target is visible and in the `device` state.
- If multiple devices are connected, set `sessionDefaults.targetId` or pass `targetId` to the tool.
- If a tool is missing, confirm its workflow appears in `enabledWorkflows`, then restart the MCP client.
- For project discovery problems, run the command from the project root and check `sessionDefaults.projectPath`.
- Re-run `androidmcp-framework setup` safely to create missing setup files. Existing config and guide files are left unchanged.

For detailed tool documentation, see the repository README and the `docs/` directory.
